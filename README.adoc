= Antora UI Chassis
:toc: preamble
:imagesdir: docs/modules/ROOT/images

Unthemed *region components* and contracts for Antora documentation UIs.
Valentus, Default UI, and other bundles *consume* this package; they do not own it.

== Layers (car metaphor)

image::layer-engine.png[Engine: Antora pipeline + UI model data,width=420]

*Engine* — Antora pipeline and the UI model it emits. Not this repo.

image::layer-chassis.png[Chassis: unthemed region parts and contracts,width=420]

*Chassis* — this repo. Mount points, viewport contracts, scheme hooks. No brand paint.

image::layer-body-kit.png[Body kit: unpainted silhouette / column shell,width=420]

*Body kit* — which parts weld where (columns, TOC side, tool-band rail). Mostly unbranded structure. Lives in Valentus / Default UI.

image::layer-paint-trim.png[Paint and trim: color, chrome, brand finish,width=420]

*Paint & trim* — palettes, type, chrome. The *logo* belongs to the site, not the theme: themes show the chassis placeholder (`packages/brand-placeholder`). Valentus today ships body kit + paint together (normal for a finished car).

== Dark mode (light / dark) and color schemes

`light-dark-mode` switches light and dark, `color-scheme` holds the token contract, color schemes and live paint, paint owns palettes, and the body kit places the toggle (top bar or footer).
`antora-dark-mode` 2.x is published from `packages/antora-dark-mode` and registers all three.
See `docs/modules/ROOT/pages/color-scheme.adoc` and the migration guide `docs/modules/ROOT/pages/migrate-dark-mode.adoc`.

== Extensions

Extensions cannot honestly be limited to additive-only work.
See `docs/modules/ROOT/pages/extensions.adoc`.

== Packages

* `packages/content-viewport` — article measure + wide-table wrapper scroll
* `packages/light-dark-mode` — dark mode: light/dark switching, saved choice, system preference, navbar or footer toggle (no colors)
* `packages/color-scheme` — `--cs-*` token contract, paint-declared color schemes (light/dark slots, picker page) and optional live paint previews
* `packages/antora-dark-mode` — `antora-dark-mode` 2.x on npm: one `require` for light-dark-mode + color-scheme + default-paint
* `packages/default-paint` — *paint layer, not chassis:* light/dark palette for the stock Antora Default UI, read through the `--cs-*` contract. Housed here so it versions with `color-scheme` and `light-dark-mode`
* `packages/brand-placeholder` — the shared placeholder logo and favicons, and the `header_logo` / `favicon` resolution partials. Sites replace it; themes never ship a brand logo (see `docs/modules/ROOT/pages/brand-placeholder.adoc`)
* `packages/soft-nav` — same-origin soft navigation bus (+ optional Antora inject extension)
* `packages/soft-nav-context` — SoftNavContext navigation context (SoftNav companion for persistent chrome)
* Diagram zoom / lightbox — use `@antora-supplemental/diagram-lightbox` (see removed `packages/diagram-zoom/README.adoc`)
* `packages/chassis-compose` — meta Antora extension bundling build-time chassis extensions (`ui-bus`, `soft-nav`, `page-state`)

== Releases (git tags)

Per-package tags: `ui-bus-vX.Y.Z`, `color-scheme-vX.Y.Z`, `light-dark-mode-vX.Y.Z`, `default-paint-vX.Y.Z`, `brand-placeholder-vX.Y.Z`, `antora-dark-mode-vX.Y.Z`, `soft-nav-vX.Y.Z`, `page-state-vX.Y.Z`, `chassis-compose-vX.Y.Z`.
`.github/workflows/release.yml` turns each package tag into a GitHub release with the package tarball attached; `antora-dark-mode-v*` tags also publish `antora-dark-mode` to npm (trusted publishing).
Meta tag `chassis-vX.Y.Z` marks the commit Facto stack and other compose pins should use (same commit as the compose package release).

== Consume from Valentus

Copy or submodule these packages. Do *not* depend on `antora-ui-default` as a dependency.
Vendor Default UI snippets by copy into the body kit if needed.
