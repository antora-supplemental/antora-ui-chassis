= Changelog

== contrast-check-v0.2.0 - 2026-10-26

* **`contrast-check` 0.2.0: suppression list.** `suppress` entries in the config or `--suppress <file>` (JSON/JSON5/YAML, Action input `suppress`) match on rule (ids, globs, aliases), selector, page glob, scheme and exact colors; each needs a `reason` and may `expires`. Suppressed findings do not count toward `--fail-on` and show as `N suppressed` (`--show-suppressed` lists them). Stale and expired entries are warnings (`--fail-on-stale` fails on them). Inline opt-out with `data-contrast-check-ignore="rule1 rule2"`. `loadConfig` is now async.

== Unreleased (demos only, no package release) - 2026-10-25

* **Demo sites move to Valentus Layout:** new `demos/valentus-layout` builds the chassis demo (`antora-playbook.yml`, top-bar light/dark toggle) and the color-scheme picker demo (`antora-playbook-picker.yml`, `scheme-demo-paint` fixture, picker page, footer Light / Dark / Auto switch) on `valentus-layout-bundle.zip` from valentus-theme v4.2.0 with `default-paint` and `brand-placeholder`, loaded from this checkout. The Default UI is no longer used for demos and stays a faithful mirror of the stock Antora UI. No published package changed.

== brand-placeholder-v0.1.0 - 2026-10-25

* **New `brand-placeholder` 0.1.0:** the shared placeholder logo for every Antora theme (moved from Valentus 4.1.0). Inline `currentColor` mark, logo/-dark/-mono SVGs, favicon.svg/.ico, apple-touch-icon, and the `brand-logo` / `head-icons` partials that resolve `site.keys.header_logo` and `favicon`. Override order: the site first, then the chassis placeholder; themes may set real logos only on their own demo site, never in what they ship. Antora extension (replaces theme copies with a warning), `scripts/bake.mjs` for release bundles, `scripts/validate-theme.mjs` brand-file validator.

== color-scheme-v0.3.0, light-dark-mode-v0.1.0, default-paint-v0.2.0, antora-dark-mode-v2.0.0 - 2026-10-25

* **New `light-dark-mode` 0.1.0 (dark mode):** light/dark switching split out of `color-scheme`. Two toggle designs on one state machine: a compact top-bar icon button (`toggle_placement: navbar`) and a labeled footer Light / Dark / Auto switch (`toggle_placement: footer`). Layout slots `light-dark-navbar-slot` / `light-dark-footer-slot`, variant partials `light-dark-toggle` / `light-dark-switch`; site beats theme beats chassis, and placed icons are kept. `follow_system`.
* **`color-scheme` 0.3.0 — breaking:** the light/dark mechanism and `ColorScheme.mode/isDark/set/toggle/subscribe` moved to `LightDarkMode`. New: light/dark slots for live paint (`slots`, `slot_policy`, per-scheme `slots`), off-slot session pick that turns automation off, `?paint=auto`, and a picker page (`picker`, footer link partial `color-scheme-picker-link`). Migration: `docs/modules/ROOT/pages/migrate-dark-mode.adoc`.
* **New `antora-dark-mode` 2.0.0 (`packages/antora-dark-mode`):** the npm name now publishes from here. A relabel that registers light-dark-mode, color-scheme and default-paint and maps the 1.x options (`site.keys.dark_mode_navbar` still honored); no CSS/JS of its own; no warning.
* **`default-paint` 0.2.0: light-mode contrast fix.** Four highlight.js token colors and `--dp-ink-faint` missed WCAG AA on light panels; new `--dp-syntax-*` tokens and a darker `--dp-ink-faint` bring axe color-contrast to 0 in light and dark for every layout on this paint (Default UI, Valentus Layout). Dark unchanged.
* **`color-scheme`: the `--cs-*` token contract is documented** (header of `color-scheme.css`, README): core `--cs-canvas`, `-elevated`, `-ink`, `-ink-muted`, `-border`, `-accent`; `--cs-accent-hover`, `-accent-soft`, `-hover`; `--cs-code-bg`, `-code-fg`; `--cs-admonition-note|tip|important|warning|caution`. The six `--valentus-*` core names stay in the contract (paints alias them).
* **`color-scheme`: `scripts/validate-paint.mjs`**, a paint-selector allowlist validator for the registry and paint CI. Errors on layout classes outside the allowlist, `@import` and external `url()`; literal colors outside token blocks are warnings (`--strict` makes them errors). `--extra=` admits a paint's declared layout prefixes.
* **`default-paint` 0.2.0: sets the full `--cs-*` contract** from its `--dp-*` palette (adds `--dp-admonition-*` per scheme), so contract layouts such as Valentus Layout render with Default UI colors.

== color-scheme-v0.2.0, default-paint-v0.1.1 - 2026-10-25

* **`color-scheme` 0.2.0 — live paint (opt-in `live_paint`):** a built site can switch its paint at view time from `?paint=<id>`, a `cs-paint` cookie, `ColorScheme.setPaint(id)` or a `postMessage` from an allow-listed origin. Only ids declared in the playbook `paints` map load; the query string never supplies a URL. The paint is in place before first paint; light/dark stays independent. Announced on `UiBus.state` `color-scheme.paint` and as a `color-scheme:paint` DOM event.
* **`default-paint` 0.1.1:** fix: the stylesheet was skipped when the live-paint config mentioned `css/default-paint.css`.

== default-paint-v0.1.0 - 2026-10-25

* **New `default-paint` 0.1.0 (paint layer, not chassis):** light and dark palette for the stock Antora Default UI, as an Antora extension that links `css/default-paint.css` after `color-scheme.css`. Light keeps the Default UI's colors; dark is ported from `antora-dark-mode`. Closes the "no default paint" gap left by `color-scheme` 0.1.0. Registry entry `layer: paint`.

== color-scheme-v0.1.1 - 2026-10-25

== color-scheme-v0.1.0 - 2026-10-25

* **`color-scheme` 0.1.0:** now a published Antora extension (`@antora-supplemental/color-scheme`) and the replacement for `antora-dark-mode`. It merges the old mechanism (no-FOUC head hook, saved choice under the same `antora-theme-mode` keys, system preference with override expiry, View Transition switch, accessible toggle binding) and adds the `ColorScheme` API, `UiBus.state` publishing and toggle re-binding after soft navigation.
* **Breaking:** `css/color-scheme.css` carries no colors any more; paint defines both palettes. Transition classes are `color-scheme-animating` / `color-scheme-vt`.
* Docs: `color-scheme.adoc` has the parity table against `antora-dark-mode` and the layer each feature moved to.

== chassis-v0.2.0 - 2026-10-24

* **New `ui-bus`:** a general event bus (`UiBus.events` for transient signals, `UiBus.state` for persistent values) with no feature knowledge. Every chassis package now talks through it.
* **`soft-nav` 0.2.0:** publishes `nav:before`, `nav:loaded`, `nav:failed` on the bus. `SoftNav.on` and the `soft-nav:*` / `doc-nav:loaded` DOM events are removed.
* **`page-state` 0.1.0:** replaces `soft-nav-context`; publishes `page.*` values. `SoftNavContext`, `SoftNavSignals` and `bindSoftNavContext` are removed.
* **`chassis-compose` 0.2.0:** bundles all three. No compatibility aliases anywhere.
