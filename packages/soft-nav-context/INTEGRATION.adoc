= SoftNavContext integration for Antora extensions

**Persistent chrome:** subscribe with `SoftNavSignals` (or `SoftNavContext.signals`). Use `bindSoftNavContext` only for boot and SoftNav `loaded` / `before`.

See link:ARCHITECTURE.adoc[ARCHITECTURE.adoc] for the three-layer model.

== Load order

1. `soft-nav.js`
2. `soft-nav-context.js` (defines `SoftNavContext`, `SoftNavSignals`)
3. `bind-soft-nav-context.js` (optional lifecycle helper)
4. Feature scripts

The Antora extension injects (2) and (3) after `soft-nav.js` in `footer-scripts` or `footer-content`.

== Page context (build time)

Register `@antora-supplemental/soft-nav-context` or `@antora-supplemental/chassis-compose` on the playbook.

== Event order (successful navigation)

[cols="1,2"]
|===
| Step | Use

| `before` | Flush scroll, prep nav
| `context` phase + **signals batch** | Update omnibox `data-*`, scope labels, path chrome
| `loaded` | Rebind article widgets; refresh scope *menu* HTML from `detail.doc` when needed
|===

== Extension pattern (persistent chrome)

[source,javascript]
----
var signals = window.SoftNavSignals || SoftNavContext.signals

signals.subscribe('componentName', function (name) {
  root.setAttribute('data-component-name', name || '')
})

signals.subscribe('scopeLabel', function (label) {
  scopeEl.textContent = label
})

bindSoftNavContext({
  onLoaded: function (nav) {
    refreshFromFetchedDoc(nav.doc)
  },
})
----

Full-object sync:

[source,javascript]
----
signals.subscribe('context', function (ctx) {
  syncChromeFromContext(ctx)
})
----

Swapped article only (no signals required):

[source,javascript]
----
bindSoftNavContext({
  onBoot: function () { boot(document) },
  onLoaded: function (nav) { boot(nav.articleHost || document) },
})
----

== Fallback without SoftNavContext

Listen to `soft-nav:loaded` and parse `detail.doc`, or use `DOMContentLoaded` for first paint.

== DOM events

`soft-nav-context:before`, `:context`, `:loaded`, `:failed` — same phases as `SoftNavContext.on`.
