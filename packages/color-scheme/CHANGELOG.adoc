= Changelog

== 0.3.0 - 2026-10-25

=== Breaking

* Light/dark switching moved to the new package `@antora-supplemental/light-dark-mode`: the no-FOUC head hook (`js/color-scheme-head.js`, removed), `antora-theme-mode` persistence, system preference, the toggle and the `ColorScheme.mode/isDark/set/toggle/subscribe` API (now `LightDarkMode.*`). Options `toggle`, `navbar` and `enabled` for light/dark belong to that package. It registers color-scheme, so replace `require: '@antora-supplemental/color-scheme'` with `require: '@antora-supplemental/light-dark-mode'` and move `live_paint` under `color_scheme:`. Migration: link:https://github.com/antora-supplemental/antora-ui-chassis/blob/main/docs/modules/ROOT/pages/migrate-dark-mode.adoc[Migrating dark mode to the chassis].

=== Added

* Live paint slots: schemes declare `slots` (`light`, `dark`), the site sets `slots: { light, dark }` and `slot_policy: declared|any`; validated at build time. `ColorScheme.assign`, `slots`, `fits`, `offSlot`, `schemes`.
* Off-slot pick: a scheme outside the current slot is pinned for the session and turns light/dark automation off; `?paint=auto`, a slot scheme or any light/dark choice turns it back on. `?paint=reset` restores the default slots.
* Picker page `color-schemes.html` with live previews (`?cs-preview=`, no writes), slot assignment and an automation banner. `picker: auto|true|false|{enabled, placement: footer|none, label, preview_page}`; auto when there are more than 2 schemes. Footer link via the `color-scheme-picker-link` partial (site, then theme, then chassis default).
  Previews render the page at four times the card width and scale it down by a quarter (`.cs-picker-shot`), so they show the desktop layout instead of a squeezed one.

== 0.2.0 - 2026-10-25

=== Added

* Live paint, opt-in with `live_paint.enabled: true`. A second inline head script picks the paint before first paint: `?paint=<id>` beats the `cs-paint` cookie (`Path=/`, `SameSite=Lax`, one year); `?paint=reset` clears it. Only ids from the playbook `paints` map load (lowercase letters and digits; hrefs validated at build time). Built-in paint links matching a map entry are switched off with `media="not all"` while another paint is active, including links parsed after the hook.
* `ColorScheme.setPaint(id)`, `getPaint()`, `paints()`. Changes go to `UiBus.state` `color-scheme.paint` and a `color-scheme:paint` CustomEvent on `document`.
* `postMessage` control for embedding pages listed in `allow_origins`: `color-scheme:paint`, `color-scheme:mode`, `color-scheme:hello`; replies `color-scheme:state` and announces `color-scheme:ready` to the parent.

== 0.1.2 - 2026-10-25

=== Fixed

* 0.1.1 crashed Antora (`this` undefined): a named single parameter makes Antora call `register(context)` unbound. `register` now destructures `({ config })`, which Antora calls with `this` bound and options passed.

== 0.1.1 - 2026-10-25 (broken; do not pin)

=== Fixed

* Playbook options (`toggle`, `navbar`, `enabled`) were ignored: `register` declared zero parameters, so Antora passed no `{ config }`. It now declares one.

== 0.1.0 - 2026-10-25

* First release as an Antora extension. Merges the mechanism of `antora-dark-mode` 1.4.6: inlined no-FOUC head hook, `antora-theme-mode` persistence (legacy `antora-theme` migrated), system preference with override expiry, View Transition switch, `#theme-toggle` binding or auto-creation with `aria-label`, `title` and `aria-pressed`.
* `ColorScheme` API (`mode`, `isDark`, `set`, `toggle`, `subscribe`); publishes `color-scheme.mode` / `color-scheme.dark` on `UiBus.state` when present; re-binds the toggle on `nav:loaded`.
* `css/color-scheme.css` no longer carries primer colors: hooks and the switch transition only. Paint supplies both palettes.
* Transition classes are `color-scheme-animating` / `color-scheme-vt` (were `valentus-theme-animating` / `valentus-theme-vt`).
