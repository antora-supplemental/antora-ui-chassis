= @antora-supplemental/contrast-check
:description: CI contrast checker for Antora sites and paints across every color scheme.

Checks a built Antora site (a directory or a URL) for color contrast in every color scheme its paint declares, and reports where it fails, where it only just passes, and what color would fix it.

* *Every scheme.* Reads the paint's `@color-schemes` manifest and runs each scheme: `light` and `dark` through the emulated `prefers-color-scheme`, every other scheme through `?scheme=<id>` in each slot it declares (slot `none` in its base mode).
* *Errors* (WCAG 2.x AA): text under 4.5:1, large text under 3:1, icons, form-control borders and focus indicators under 3:1, keyboard focus with no visible change, `--cs-*` token pairs under their threshold. Text runs through axe-core `color-contrast`.
* *Warnings*: ratios that pass by less than the near margin (0.5), links without an underline under 3:1 against the text around them, focus or hover states too similar to rest, icons on a fill under 4.5:1, near-identical colors in one paint block, hard-coded colors outside tokens, and an optional APCA Lc readout.
* Every finding has the page, scheme, selector, colors, ratio and a suggested color. Suggestions keep hue and saturation and move lightness only.

== Install

[source,json]
----
"devDependencies": {
  "@antora-supplemental/contrast-check": "github:antora-supplemental/antora-ui-chassis#contrast-check-v0.1.0&path:packages/contrast-check"
}
----

It drives Chrome or Chromium through `playwright-core` (no browser download). It finds `/usr/bin/google-chrome`, `/usr/bin/chromium` or Chrome on Windows; set `CONTRAST_CHECK_CHROME` to a browser path otherwise.

== CLI

[source,sh]
----
contrast-check build/site                       # every page (up to 20), every scheme
contrast-check build/site --pages "index.html,guide/**/*.html" --schemes light,dark,slate
contrast-check https://docs.example.org --pages index.html
contrast-check build/site --json=contrast.json --fail-on warning
----

[cols="1,3"]
|===
| `--pages <list>` | Comma-separated pages or globs, site-relative. `_` folders and `404.html` are skipped.
| `--max-pages <n>` | Page cap (20).
| `--schemes <ids>` | Only these scheme ids.
| `--paint <file.css>` | Paint stylesheet(s) for the manifest and static checks; repeatable. Default: discovered from the first page.
| `--config <file>` | Config file. Default `./contrast-check.config.json` when present.
| `--near <ratio>` | Near-threshold margin (0.5).
| `--apca` | Add APCA Lc to text findings.
| `--no-focus` | Skip the focus and hover checks.
| `--json`, `--json=<file>` | JSON report to stdout or a file.
| `--fail-on error\|warning\|none` | Exit 1 on errors (default), on any finding, or never (report only).
| `--strict` | Same as `--fail-on warning`.
| `--suppress <file>` | Suppression list (JSON, JSON5 or YAML; repeatable), added to the config's `suppress`. See <<Suppressions>>.
| `--show-suppressed` | List suppressed findings with the entry and reason.
| `--fail-on-stale` | Exit 1 when a suppression matched nothing or has expired.
| `--quiet` | Totals only.
|===

Exit codes: 0 clean (under `--fail-on`), 1 failed, 2 usage or setup error.

Under GitHub Actions it prints `::error` / `::warning` annotations (with `file=` pointing at the page or paint and a `title`), and appends a summary table to `$GITHUB_STEP_SUMMARY`.

== Config

`contrast-check.config.json` (see `contrast-check.config.example.json`): `thresholds` (`text`, `large`, `nonText`, `link`), `nearMargin`, `similarState`, `apca`, `pages`, `maxPages`, `schemes`, `paints`, `tokens`, `failOn`, `ignore` (`selectors`, `rules`, `pages`), `maxAnnotations`, `suppress`, `failOnStale`. Unknown keys are an error. The file may also be `contrast-check.config.json5` or `.yaml`/`.yml` (needs the optional `json5` / `yaml` packages, installed by default).

`ignore` drops whole rules, pages or selectors silently; prefer `suppress` for known findings, which needs a reason, can expire, and is reported.

== Suppressions

A suppression marks a known finding as accepted. Suppressed findings do not count toward `--fail-on`; the totals read `3 error(s), 1 warning(s), 4 suppressed`, and `--show-suppressed` lists them with their reasons (JSON: `suppressed`, `counts.suppressed`).

Entries come from the config's `suppress` array and from `--suppress <file>` (an array, or `{ "suppress": [...] }`; JSON, JSON5 or YAML) or the Action's `suppress` input. Each entry matches on any combination of these, and all given fields must match:

[cols="1,3"]
|===
| `rule` / `rules` | Rule id (`color-contrast`, `token-pair`, ...), glob (`focus-*`), `all`, or an alias: `link-distinguishable` (`link-not-distinct`), `near-identical` (`near-identical-colors`), `faint-border` (`control-boundary`, `token-boundary`), `hover-no-change` (`hover-unchanged`), `hardcoded-color` (`hard-coded-color`).
| `selector` | The finding's selector: exact, substring, or `/regex/flags`.
| `page` / `pages` | Site-relative page glob (`guide/**/*.html`; leading `/` optional). Paint-file findings have no page and never match.
| `scheme` / `schemes` | Scheme id (`dark`) or run (`dark/dark`).
| `colors` (`fg`, `bg`), or `fg` / `bg` | Exact colors, compared after normalizing (`#777` = `#777777` = `rgb(119,119,119)`).
| `reason` | Required.
| `expires` | Optional `YYYY-MM-DD`. After that day the entry is ignored and reported as `suppression-expired`.
| `id` | Optional name for reports (default `config#2` or `<file>#2`).
|===

Matching runs per page and scheme before findings are merged, so a page or scheme filter suppresses exactly that part and the rest still reports.

An entry that matches nothing is reported as a `suppression-stale` warning (console, `::warning` annotation, step summary) so the list does not rot. Stale and expired entries do not fail the run unless `--fail-on-stale` (config `failOnStale: true`).

[source,yaml]
----
# contrast-check.suppress.yaml
suppress:
  - rule: color-contrast
    selector: .search-input
    scheme: [dark]
    reason: Placeholder text, not content; tracked in #42
    expires: 2027-03-31
  - rule: hover-no-change
    page: api/**/*.html
    reason: Generated API nav uses focus styles only
----

=== Inline opt-out

Mark an element (or an ancestor) in the page: `data-contrast-check-ignore="focus-not-visible hover-no-change"` suppresses those rules (ids, aliases or globs) for that element; an empty value suppresses every rule. These show as suppressed by `inline`. Static paint and token findings have no element and need a `suppress` entry.


== GitHub Action

[source,yaml]
----
- uses: antora-supplemental/antora-ui-chassis/packages/contrast-check@contrast-check-v0.2.0
  with:
    site: build/site
    pages: "index.html,**/*.html"
    fail-on: error   # or warning, or none for report only
----

Inputs: `site`, `pages`, `max-pages`, `schemes`, `paint`, `config`, `fail-on`, `suppress` (suppression file), `show-suppressed`, `fail-on-stale` (`"true"`/`"false"`), `json` (report path, default `contrast-check.json`), `args`. GitHub-hosted Ubuntu runners already have Chrome.

== Dynamic UI states

A static page load only sees what is visible at rest. Search dropdowns, menus, popovers and other extension UI are `display:none` or not rendered yet, so their colors are never measured. States fix that: after the normal checks, each page is reloaded once per state, the state's steps run, and axe plus the probe run again on the result. Findings carry `state`.

Every run uses `prefers-reduced-motion: reduce` and disables transitions and animations, so the end state is measured, not a frame mid-fade.

Presets (CLI `--state <name>`, repeatable; Action input `states: search-results,fixtures`; config `"states": ["search-results"]`):

`search-results`:: clicks `#search-input`, types a query and waits for Lunr / antora-search-chat results.
`fixtures`:: runs every fixture an extension registered on `window.contrastCheckFixtures` (`{ name, run() }`) and dispatches `contrast-check:state` on `document`. Extensions use it to render sample JS UI (antora-search-chat opens its results with a sample query).
`reveal-hidden`:: forces hidden-but-present nodes visible: closed `<details>`, `aria-expanded="false"` controls and their `aria-controls` targets, `[hidden]`, and `display:none` / `visibility:hidden` elements that contain text. Noisy on sites with many collapsed menus; use it as a report step or with suppressions.

Custom states go in the config:

[source,json]
----
{ "states": [
  "search-results",
  { "name": "nav-open", "pages": ["**/*.html"], "steps": [
    { "click": ".navbar-burger" },
    { "waitFor": ".navbar-menu.is-active" }
  ] }
] }
----

Steps: `click`, `hover`, `fill` / `type` (with `text`), `press` (a key), `waitFor` (selector, `timeout` ms), `wait` (ms), `reveal: true`, `fixtures: true | [names]`. A failed step reports `state-not-reached` (warning) unless the step has `optional: true`.
== Rules

[cols="1,1,3"]
|===
| Rule | Level | Meaning
| `color-contrast` | error | axe-core: text under 4.5:1 (large text 3:1).
| `token-pair` | error | A `--cs-*` pair (ink/canvas, accent/canvas, code fg/bg, ...) under its threshold. Translucent surfaces are composited over `--cs-canvas`.
| `icon-contrast` | error | An icon (svg, icon font) under 3:1 against its fill.
| `control-boundary` | error | A form control whose fill does not stand out and whose border is under 3:1.
| `focus-indicator` | error | Focus outline, ring or border under 3:1 against the background.
| `focus-not-visible` | error | Keyboard focus changes nothing visible. The browser's own ring (`outline-style: auto`) passes.
| `near-threshold`, `token-pair-near` | warning | Passes by less than `nearMargin`.
| `link-not-distinct` | warning | A link without an underline under 3:1 against the text around it.
| `focus-too-similar`, `hover-too-similar`, `hover-unchanged` | warning | State change under `similarState` (1.2:1), or none. Reported once per selector, listing the schemes.
| `icon-on-fill` | warning | Icon at 3:1 or more but under 4.5:1 on its fill.
| `token-boundary` | warning | `--cs-border` on `--cs-canvas` under 3:1; fine for decoration.
| `near-identical-colors` | warning | Paint colors in one block within OKLab ΔE 0.02.
| `hard-coded-color` | warning | Literal colors outside tokens (color-scheme's paint validator).
| `scheme-not-applied` | warning | `?scheme=<id>` did not take effect.
|===
